# NEON SNAKE · общий рейтинг

Готовый репозиторий: игра, Node.js API и SQLite. Без npm-зависимостей и внешних ключей.

## Запуск

Установите Node.js 24 LTS, откройте терминал в папке проекта:

```sh
npm test
npm start
```

Откройте http://localhost:3000. База создаётся автоматически в `data/snake.sqlite`.
Не открывайте HTML двойным щелчком: онлайн-рейтинг требует запуска сервера.

## GitHub и Render

1. Создайте пустой репозиторий на GitHub.
2. Загрузите содержимое этой папки в корень репозитория, включая `.github`, `.gitignore`, Dockerfile и render.yaml. Не загружайте папку data.
3. В Render выберите **New → Blueprint**, подключите репозиторий и проверьте стоимость предложенного сервиса перед подтверждением.
4. Render прочитает render.yaml, соберёт Docker-образ и подключит постоянный диск `/app/data`.
5. Откройте выданный Render HTTPS-адрес. Он общий для игры и API; его можно отправить друзьям.

**Render-конфигурация платная:** starter web service и постоянный диск 1 ГБ. Диск нужен, чтобы результаты сохранялись после перезапусков и деплоев. Никакие платные сервисы при подготовке проекта не создавались.

GitHub хранит код. GitHub Pages не запускает этот Node.js API, поэтому для текущей сборки используйте Render или собственный сервер с постоянным диском.

## Docker / собственный сервер

```sh
docker compose up --build -d
```

Локальный адрес: http://localhost:3000. Именованный Docker volume сохраняет базу. Команда `docker compose down -v` удалит его вместе с рейтингом — не используйте её, если данные нужны.
Для публичного сервера настройте HTTPS через reverse proxy, установите NODE_ENV=production и сохраняйте volume. Локальный compose использует development, чтобы cookie работала по HTTP.

## Рейтинг

- Анонимный профиль создаётся автоматически через HttpOnly cookie; никакой регистрации.
- Ник и лучший результат публичны. Ники не уникальны и не подтверждают личность.
- Один лучший результат на профиль в каждой из четырёх таблиц: классика/приключение × стены/сквозь края.
- При равных очках выше тот, кто раньше набрал результат. Zen вне рейтинга.
- Топ-50 и собственная позиция, даже вне топ-50. Обновление каждые 30 секунд и после завершения партии.
- Только законченные партии. Выход в меню и перезапуск не публикуют текущие очки.
- Очистка cookies или другой браузер создаёт новый профиль. Аккаунтов и синхронизации между устройствами нет.
- При сетевой ошибке можно повторить последнюю отправку, пока вкладка открыта. Повторная отправка одной партии не дублирует результат. Следующая законченная партия заменяет неотправленную в очереди.
- Партия должна начаться при доступном API. Иначе она остаётся локальной; офлайн-очки задним числом не принимаются.

## Проверки и пределы защиты

Сервер создаёт идентификатор партии, привязывает его к профилю и режиму, проверяет диапазоны, количество бонусов и минимальную длительность. Отправка идемпотентна. SQL параметризован, ники выводятся через textContent, есть ограничение запросов и проверка источника.

**Это рейтинг для дружеской игры, не полноценный античит.** Игра исполняется в браузере; подготовленный пользователь может подделать правдоподобный результат. Для турниров нужен серверный расчёт или детерминированный replay с проверкой каждого хода. Не используйте для денежных призов.

Ограничитель запросов хранится в памяти процесса. Эта SQLite-сборка рассчитана на один экземпляр сервера. Для большого трафика нужен общий PostgreSQL и распределённый rate limiter. Сессии партий хранятся до 24 часов; лучшие результаты и профили остаются в базе.

## Сохранность данных

Переменные: PORT (по умолчанию 3000), DB_PATH (по умолчанию data/snake.sqlite), NODE_ENV. Секретов в репозитории нет, session cookie не логируется и её хеш хранится на сервере.
Делайте регулярные резервные копии базы. Для простой файловой копии остановите сервис и скопируйте весь каталог data; копирование только sqlite при работающем WAL может потерять свежие записи. Не коммитьте базу в GitHub.

## Файлы

`dist/index.html` — игра; `dist/online.js` — интерфейс рейтинга; `server.mjs` — сервер и миграции; `test/` — API-тесты; `.github/workflows/test.yml` — CI; `render.yaml` — деплой; `compose.yaml` — локальный Docker.

Документация: https://render.com/docs/blueprint-spec · https://render.com/docs/disks · https://nodejs.org/api/sqlite.html

## Netlify: публикация игры

В корне есть netlify.toml. При подключении GitHub выберите ветку main, оставьте Base directory и Build command пустыми, Publish directory — dist. При ручной загрузке перетащите папку dist: внутри неё находятся index.html и online.js.

Эта конфигурация публикует только клиентскую игру. Node.js API и SQLite из server.mjs не запускаются при статической публикации на Netlify, поэтому общий рейтинг на таком деплое недоступен. Для него нужна отдельная адаптация серверной части или подключение работающего API. Локальная игра и личные рекорды работают.
